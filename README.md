# Лунная алхимия — React + Spring Boot + H2

Полный локальный веб-прототип. React отвечает за интерфейс, Java — за игровые
правила и REST API, H2 — за хранение прогресса. Все находится в одной папке.
Это новая реализация по исходной концепции, а не миграция существующего сохранения.

## Требования

- JDK 17+ (для простого старта рекомендуем JDK 21).
- Maven 3.6.3+.
- Node.js 22 LTS и npm.
- Интернет для первой загрузки Java/JS-зависимостей.

Проверить в CMD:

```bat
java -version
javac -version
mvn -v
node -v
npm -v
```

Если команда не найдена, установите соответствующую программу и добавьте ее bin
в Path, затем откройте новое окно CMD. JAVA_HOME должен указывать на папку JDK.
Maven Wrapper, node_modules, готовый JAR и package-lock.json не включены.
Первый npm install создаст lock-файл: сохраните его для воспроизводимых сборок.

## Самый простой запуск Windows

1. Распакуйте архив полностью.
2. Дважды щелкните start-backend.cmd и дождитесь строки Started Application.
3. Дважды щелкните start-frontend.cmd и дождитесь запуска Vite.
4. Откройте http://localhost:5173 в браузере.
5. Оба окна оставьте открытыми. Для остановки нажмите Ctrl+C в каждом.

## Ручной запуск через CMD

Первое окно, из распакованной папки moonstone-web:

```bat
cd backend
mvn spring-boot:run
```

Второе окно, из той же корневой папки:

```bat
cd frontend
npm install
npm run dev
```

Интерфейс: http://localhost:5173
API для проверки: http://localhost:8080/api/state

Vite проксирует /api на 127.0.0.1:8080. Запросы браузера идут на тот же origin,
поэтому отдельный permissive CORS не нужен. Серверы слушают только loopback:
этот прототип рассчитан на локальную игру, не на публикацию в интернет.
Vite strictPort=true: занятый порт 5173 вызывает ошибку вместо незаметной смены.
При изменении порта backend обновите frontend/vite.config.js.

## Один JAR с интерфейсом

Запустите build-single-jar.cmd из Проводника. Он соберет frontend, скопирует dist
в статические ресурсы Spring Boot и выполнит mvn clean package с тестами.
Затем из папки backend выполните:

```bat
java -Dfile.encoding=UTF-8 -jar target\alchemy-web-1.0.0.jar
```

Откройте http://localhost:8080 — React и API обслуживает один процесс Java.
Node.js нужен для сборки, но не для запуска уже собранного JAR.
SPA не использует маршруты браузера, все разделы переключаются в одном URL.
Если заново меняете React-код, пересоберите JAR этим скриптом.

## Как играть

Старт: 150 камней, 6 видов ингредиентов, 8 рецептов (7 секретных), один заказ.

1. В Лаборатории добавьте +1 Лунную траву и +1 Росу, нажмите «Сварить».
2. В Книге открытий появится Зелье исцеления с составом и номером 1.
3. В Заказах отдайте его Травнице Мире и получите 40 камней.
4. В Магазине купите коллекцию за 60 или редкие ингредиенты.
5. В Заказах пригласите новых клиентов (максимум 5 активных).
6. Кнопка сбора дает +1 каждого неэксклюзивного ингредиента за игровой ход.
   В реальном времени ожидать не нужно. Это помогает избежать тупика без денег.

Ингредиенты смешиваются точным мультимножеством: порядок не важен, количества
важны. Две Росы + Светлячок = Сон феи. Одна Роса + Светлячок — неверная смесь.
Неверная смесь расходует ингредиенты, а мутная жижа утилизируется и не хранится.
Недостаточные остатки или неверный запрос не расходуют ресурсы.

Коллекция открывает от 2 до min(5, оставшиеся) неизвестных секретных рецептов.
Если осталось меньше двух, покупка отменяется без оплаты. Готовые зелья она
не дает. Книга показывает точные составы и источник BREWING/COLLECTION.
Заказ отдает одно зелье и награждает ровно один раз.

## База и транзакции

H2 — настоящий файловый JDBC-источник Java-сервера, а не localStorage браузера.
Изменения сохраняются в backend/data/moonstone.mv.db при запуске из backend.
Расположение относительно рабочего каталога: всегда запускайте сервер из backend,
чтобы случайно не создать второе сохранение. Не запускайте два сервера с одной БД.
Для новой игры остановите сервер и удалите backend/data.

Связи:
- Recipe 1:N RecipeIngredient N:1 Ingredient.
- Player 1:N Inventory N:1 Ingredient.
- Player 1:N Discovery N:1 Recipe.
- Player 1:N PotionStock N:1 Recipe.
- Player 1:N CustomerOrder N:1 Recipe (targetRecipe).

RecipeIngredient — отдельная сущность, а не прямой ManyToMany: она хранит quantity.
Уникальны пары игрок/ингредиент, игрок/рецепт, рецепт/ингредиент, а также
(player_id, unlock_order) и Recipe.signature. Signature — сортированная запись
ID:количество, она запрещает неоднозначность составов. При добавлении редактора
рецептов нужно атомарно обновлять и состав, и signature.

Каждая изменяющая операция @Transactional и берет PESSIMISTIC_WRITE на игроке.
Состояние игрока обновляется из БД после взятия блокировки, прежде чем его менять.
Это сериализует конкурентные покупки, варку и открытия одного игрока.
Player.nextUnlockOrder выдает следующий порядковый номер. Discovery не дублируется.
RuntimeException откатывает транзакцию целиком; неверный эксперимент возвращает
обычный результат, поэтому намеренный расход ингредиентов фиксируется.
Сущности не передаются в JSON: контроллер возвращает DTO, без циклов JPA.
Состояние GET не блокирует игрока и при конкуренции может отображать промежуточный
срез нескольких чтений; следующая перезагрузка интерфейса актуализирует его.

Для прототипа используются public-поля JPA и EntityManager вместо набора простых
репозиториев. Это Spring Data JPA/Hibernate инфраструктура; отдельные
JpaRepository можно выделить при расширении. Баланс хранится прямо в Player.
Hibernate ddl-auto=update удобен для старта, но не заменяет миграции Flyway.
При эволюции схемы переходите на миграции и ddl-auto=validate.

## REST API

| Метод | URL | JSON |
|---|---|---|
| GET | /api/state | — |
| POST | /api/brew | {"ingredientIds":[1,2]} |
| POST | /api/shop/ingredient | {"ingredientId":5,"quantity":1} |
| POST | /api/shop/collection | {} |
| POST | /api/orders | {} |
| POST | /api/orders/{id}/deliver | {} |
| POST | /api/gather | {} |

POST возвращает {"message":"..."}. Игровые отказы и поврежденный JSON — HTTP 400.
После успешной команды React запрашивает новое состояние. На время запроса
кнопки действий блокируются; ошибки показываются над интерфейсом.
Это не обеспечивает идемпотентность повторных HTTP-запросов: покупка, отправленная
повторно извне, будет новой покупкой. Статус заказа защищает от повторной награды.

## Проверка

```bat
cd backend
mvn test
```

7 тестовых методов: варка/повторное открытие, пропорции и неудачная смесь,
коллекция и порядок, заказ/награда, отказы без изменения состояния, сбор,
REST state и валидация. Тесты используют отдельную in-memory H2 и не трогают
сохранение. Есть MockMvc-проверка API, но нет браузерных E2E и нагрузочных тестов.

```bat
cd frontend
npm install
npm run build
```

Важно: при генерации ZIP не было Java/Maven и доступа к npm-зависимостям.
Полная сборка, JUnit и браузерный запуск не выполнялись. Это исходный прототип,
не проверенный релиз. Архив проверен на целостность и наличие основных файлов.

## Ограничения

Один локальный игрок, без регистрации, авторизации и Spring Security.
В интернет не публиковать как есть: нужны аутентификация, CSRF/другая схема
защиты запросов, миграции, проверки БД и аудит зависимостей.
Флаг exclusive означает отсутствие в бесплатном сборе; начальные редкие запасы
выдаются для демонстрации. Нет эффектов зелий, дедлайнов, уровней и ротации лавки.
Открытые рецепты загружаются в память; для большого каталога нужны пагинация
и оптимизация N+1. Сбор бесплатный и неограниченный — это прототип экономики.
Старое консольное сохранение не переносится: схема и имена таблиц изменились.
